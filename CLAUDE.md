# EasyITP

ITP (vehicle inspection) station management app. One manager = one ITP station: ITP records, reminders for expiring ITPs (WhatsApp/SMS), appointments calendar, reports, CSV import/export. Admin manages manager accounts and sees aggregated numbers only. JWT auth.

## Stack
- Backend: Spring Boot 3.3.5, Java 17, Maven (`mvnw`), JPA + PostgreSQL, Spring Security + JWT, Lombok, commons-csv.
- Frontend (`frontend/`): React 19 + TypeScript, Vite, Tailwind 4, axios, react-router, MUI X Scheduler (calendar), Vitest.

## Layout
- `src/main/java/org/example/easyitp/` — `controller/`, `service/`, `repository/`, `entity/`, `dto/`, `security/` (JwtUtil, JwtRequestFilter, CurrentUser), `config/` (SecurityConfig incl. CORS, DataSeeder).
- `src/main/resources/application.properties` — config via env: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET` (>= 32 bytes), `ADMIN_PASSWORD`, `ALLOWED_ORIGINS`, `SHOW_SQL`, `RESEND_API_KEY`, `MAIL_FROM`, `APP_URL`, `CRON_SECRET`, `ANTHROPIC_API_KEY`, `GOOGLE_PLACES_API_KEY` (optional), `API_URL` (backend public URL for the Netopia IPN), `NETOPIA_URL` / `NETOPIA_API_KEY` / `NETOPIA_POS_SIGNATURE` and `PLATFORM_OBLIO_EMAIL` / `_SECRET` / `_CIF` / `_SERIES` (optional, subscriptions), `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` (optional, push notifications; generate once with `scripts/vapid-keys.sh`), `PORT` (default 8080). `JWT_SECRET`, `ADMIN_PASSWORD` (only for the first start on an empty DB) and `ALLOWED_ORIGINS` have no defaults: startup fails without them; local defaults live in `application-dev.properties` (profile `dev`, enabled by `./mvnw spring-boot:run`; for `java -jar` pass `--spring.profiles.active=dev` or the env vars). Default JVM time zone is Europe/Bucharest (`TimeZoneConfig` + `-Duser.timezone` in the Dockerfile).
- Schema: **Flyway** migrations in `src/main/resources/db/migration` (`V1__baseline.sql` = schema at the switch, skipped on existing DBs via `baseline-on-migrate` + `baseline-version=1`; `V2` drops Hibernate's enum CHECKs). Hibernate runs with `ddl-auto=validate`, so every entity change needs a new `Vn__description.sql` (never edit an applied migration; no enum CHECK constraints). Tests on H2 skip Flyway (`create-drop`); verify new migrations on a local Postgres (`docker run postgres:16`) both on a fresh DB and on an existing one.
- `frontend/src/` — `api/` (one module per backend controller, shared `axiosInstance.ts`), `components/` (pages + modals; pages are lazy-loaded in `App.tsx`), `context/` (`AuthContext.tsx` provider, `auth.ts` context + `useAuth`), `utils/` (pure helpers with `*.test.ts`), `types/index.ts`.
- Public booking page `/programare/:slug` (no login): backend `/api/public/**` is permitAll, rate-limited per IP (`BookingRateLimiter`) with a honeypot field; the phone must be a real mobile number (`PhoneNumbers.requireMobile`, Google libphonenumber; no prefix = Romanian, others with +/00 country prefix; stored "0722 123 456" or "+49 1512 3456789", which `SmsSender.phoneDigits` still reads), checked live in the page with `utils/phone.ts` (libphonenumber-js/max, same rules); manager appointments only need a valid number if one is typed (`optionalValid`), and an unchanged legacy number never blocks an edit/move; settings per station on `AppUser.booking*`. Capacity: each appointment has `vehicleCategory` + `durationMinutes` (legacy null = 30 min); per-station durations per vehicle type in `AppUser.bookingDurations` (`InspectionDurations`, defaults car 20 / 4x4 30 / van 45); optional prices per type in `AppUser.bookingPrices` (`InspectionPrices`, `VehicleTypeDTO.price`; public only when `bookingShowPrices`; `AppointmentDTO.listPrice` and the inspector prefill fill the ITP price); daily break `bookingBreakStart/End` (no slot overlaps it, the break end is a slot); closed days = Romanian legal holidays (`RomanianHolidays`, Orthodox Easter/Rusalii, on unless `bookingHolidaysClosed` = false) + station days (`station_closed_days`, V29, `POST/DELETE /api/account/closed-days`, max 92 days, past ones purged by the morning run; `ClosedDaysEditor` in the booking card): no online slots, listed in `PublicStationDTO.closedDays` (booking and `/p/:token` pages skip them, `utils/closedDays.ts`), warning in `AppointmentModal` (manager can still book); online slots = the type's own grid plus the end times of other bookings, offered only if the whole interval fits on one of `bookingCapacity` lines. Lines: `bookingCapacity` = number of ITP lines, optional names in `AppUser.bookingLineNames` (one per line); edited only in the „Linii ITP” card (`LinesCard`, `/account#linii`, `GET/PUT /api/account/lines` {count, names}, shows each line's default inspectors; fewer lines clears the removed lines from inspectors' `defaultLine` / schedule days); `BookingSettingsDTO.capacity`/`lineNames` are read-only for the booking card (null on save = unchanged); every appointment has `Appointment.line` (V22 `line_no`, null = legacy). `LinePlanner` gives legacy ones the first free line per day (display only) and picks a line for new ones: online booking and the client's move take the first line free for the whole interval (preferring the current one); the manager's explicit `line` is kept even if busy, `line: null` = auto (keep the current line if free). Calendar has two views (`calendarMode` per device): MUI week/day/month and our own `LinesDayView` (one column per line, click = new appointment on that line, mouse drag to another time/line; touch opens the modal); `AppointmentModal` picks the line and shows which are free.
- Morning run (`DailyJobService.runOnce`): digest, auto SMS, appointment reminders, review requests, plan notices, Google ratings, purges. Triggered by the app's own clock `DailyJobScheduler` (`daily.cron`, default every 10 min 07:00–11:50 Mon–Sat, Europe/Bucharest; off in tests via `daily.scheduler.enabled=false`; Render stays awake thanks to UptimeRobot) and, as a fallback, by GitHub Actions (`daily-digest.yml`, several tries after 07:00; GitHub schedules can be hours late) calling `POST /api/internal/daily-digest` with `X-Cron-Secret`. The day is claimed in `job_runs` (row lock), so it runs once per day whatever triggers it.
- Daily digest email: `DigestService` builds an HTML and a WhatsApp text version and claims the day atomically per manager (`AppUserRepository.claimDigest`, released on failure), so overlapping runs never send twice; each manager picks the channel: `EmailService` (Resend) or `WhatsAppService` (CallMeBot, free personal-use API, per-manager key never returned to the client). External HTTP calls have timeouts (`HttpTimeouts`); email retries once with a Resend `Idempotency-Key`, WhatsApp retries only when the connection failed. Never commit API keys.
- Registration scan: `POST /api/itp/scan-registration` (multipart `image`) sends the photo of the Romanian talon to Claude Haiku (`RegistrationScanService`, forced tool use, fields A/E/D.1/D.3/B/C.2.x), maps make/model through the car dictionary; the photo is never stored, 200 scans/user/day cap. Frontend shrinks the photo first (`utils/image.ts`). Talon only, never ID cards (GDPR).
- Fleets (B2B): a manager creates `Fleet`s (company, CUI, plates in `fleet_plates`) and one login per fleet (`AppUser` with role `FLEET` + `fleetId`). Manager API `/api/fleets/**`, fleet portal `/api/fleet-portal/**` (`FleetService`): vehicles matched by normalized plate against the station's latest ITPs, and a monthly statement (informative, not a fiscal invoice; CSV + printable page built in `utils/fleet.ts`). `SecurityConfig` limits FLEET to the portal and `/api/account/me|password`.
- Inspectors (team): `Inspector` entity (`inspectors`, V23 copied the old `station_inspectors` names and dropped it): name (unique per station, case-insensitive), phone, color (8-hue validated palette, same order in `InspectorService.COLORS` and `utils/inspectors.ts`), active, `defaultLine`; attestation = the station deadline of kind ATESTAT_INSPECTOR titled with the name (set from the inspector form on Pro, so it reaches the dashboard alert and the digest). `ItpRecord.inspector` stays the name (sheet, history, reports); renaming updates the station's ITPs. `LineShift` (`line_shifts`, `shift_date`) overrides who works a line on a day (null = nobody); `InspectorService.lineInspectors` = defaults + overrides. `Appointment.inspectorId` (explicit, null = the line's) and read-only `AppointmentDTO.lineInspectorId`. API `/api/inspectors/**` (MANAGER): CRUD, `/shifts`, `/dashboard?from&to` (Pro, `OWNER_REPORTS`; per inspector ITPs, revenue, failed, days worked, appointments/no-shows, today's line; daily rows for the stacked chart). `/api/account/inspectors` GET = active names (ITP form), PUT = legacy name list sync. Page `/inspectori` (`InspectorsPage`: KPIs, attestation alert, cards, `InspectorStackedChart`, table, „Cine e pe linii”, team list + `InspectorModal`; desktop nav only, phones reach it from Contul meu). Calendar lines view shows/changes the line's inspector in the column header; the appointment modal picks one; „Începe ITP” prefills the appointment's inspector. Weekly schedule: `Inspector.schedule` (`inspector_days`, V24; weekday 1-7, optional line overriding `defaultLine`, optional hours; empty = no fixed schedule = every day); `InspectorService.lineOn/worksOn` drive the default line inspector per date, `LineShift` still overrides. Leaves: `InspectorLeave` (`inspector_leaves`, V26, one row per day, kind CONCEDIU / MEDICAL / LIBER + note; ranges = consecutive days, `InspectorService.ranges`), `GET /api/inspectors/leaves?from&to`, `PUT /{id}/leaves` {from,to,kind,note} (max 92 days, replaces), `DELETE /{id}/leaves?from&to`; a day on leave removes the inspector from the default line (`defaultFor`), explicit `LineShift`s still win; shown in the dashboard (`leaveToday`), `LeavePlanner` (month grid on /inspectori: click a day, Shift+click a range), `InspectorModal` and the inspector's own page. Own accounts: `AppUser` role INSPECTOR with `inspectorId` (V24), login `prenume.nume@<booking slug or statie<id>>` (`InspectorLogins`, not a real email: forgot-password skips them, the login field is text), created/reset by the manager (`PUT/DELETE /api/inspectors/{id}/account`, min 8 chars) or, for inspectors that existed at deploy, by the Java migration `config/migration/V25__inspector_accounts` (a Spring bean Flyway picks up; password `changeme`). A password set by someone else sets `passwordChangeRequired`: `JwtRequestFilter` then grants only ROLE_PASSWORD_CHANGE (just `/api/account/me|password`), the frontend shows `ForcePasswordChange`; changing it clears the flag (new password must differ). Deactivating/deleting the inspector disables/deletes the account. Portal `/api/inspector-portal/**` (`InspectorPortalService`): `/me` (schedule, month ITPs), `/day?date` (works?, line, hours, own appointments = explicit or line's), `PUT /appointments/{id}/status` (only SCHEDULED/NO_SHOW, own only, not once an ITP exists: „Finalizat” comes only from a saved ITP), `GET /appointments/{id}/prefill` + `POST /appointments/{id}/itp` (ItpFormDTO; saved on the station via `ItpService.createItpEntry(form, station, actor)` with the inspector's name forced and the inspector's login as audit actor, deadlines untouched, consent only sent when ticked; completes the appointment); `GET /api/cars/**` is readable by INSPECTOR. UI `InspectorHomePage` („Ziua mea”, phone-first, „Începe ITP” → `InspectorItpModal`). `ReportService` keeps the per-inspector monthly rows and retention (vehicles with an ITP last year that reached expiry: returned this year vs lost, with a call list). Admin gets neither names nor the lost-client list (aggregates only).
- Installable app + push (PWA): `public/manifest.webmanifest`, icons in `public/icons/`, hand-written `public/sw.js` (registered in production by `utils/device.ts` `setupDevice()` from `main.tsx`; navigations network-first with the cached shell offline, `/assets/*` cache-first, push + notificationclick; `vercel.json` serves it `no-cache`). Push = Web Push without libraries: `WebPush` (RFC 8291 aes128gcm + VAPID ES256, tested against the RFC 8291 example), `PushService` (subscriptions in `push_subscriptions` V30 with the account's `tokenVersion`, so a password change/deactivation silently drops them; endpoints only on known push hosts (no SSRF); max 10 per account; sent after commit on a small thread pool, `push.async=false` in tests; 404/410 delete), `PushGateway` (HTTP, mocked in tests). Off without valid VAPID keys (the pair is verified at startup). API `/api/push/status|subscribe|unsubscribe|test` (MANAGER + INSPECTOR). Sent for every `NotificationService.add` (manager) and, from `BookingEvents`, to the appointment's inspector account when it's today/tomorrow. UI `AppDeviceSettings` (install button / iOS instructions, enable/disable/test) in Contul meu (`/account#aplicatie`) and at the bottom of „Ziua mea”. Offline = today only: `utils/offline.ts` keeps today's agenda (`TodayAgenda`) and the inspector's day/me in localStorage per account (read-only when the network fails, „fără internet · salvate la …”), `OfflineBanner`; logout unsubscribes this device and clears the copies.
- Dark mode: `ThemeProvider` (`context/ThemeContext.tsx`, `useTheme` in `context/theme.ts`) sets `<html data-theme>`; an inline script in `index.html` applies it before paint. `index.css` remaps the slate scale via Tailwind CSS variables, maps `bg-white`/`.modal-panel` to `--surface`, and overrides colored tints per class (generated block). Don't add `dark:` classes everywhere; use `var(--surface)` / `var(--color-slate-*)` for inline colors, and the `dark:` variant only for one-off fixes. MUI calendar gets its own dark theme.
- Security: errors go through `config/ApiExceptionHandler` as `{"message"}` (bad dates/params/body and DB constraint errors -> 400); don't add per-controller handlers. JWT carries `tv` = `AppUser.tokenVersion`; `revokeTokens()` on password change/reset, deactivation and fleet password change (password change returns a new token). Login: emails lowercased + `findByEmailIgnoreCase`, failed attempts limited per email and per IP (`LoginRateLimiter`), dummy bcrypt for unknown emails. Client IP for limits = `CF-Connecting-IP` (`security/ClientIp`; Render is behind Cloudflare and keeps client-sent X-Forwarded-For). CSV cells go through `CsvCells.cell` (quoting + formula neutralizing). Admin report export has no plates/names. Frontend security headers + CSP in `frontend/vercel.json` (no inline scripts: the theme script is `public/theme-init.js`; `connect-src` must list the backend URL).
- Clients (B1): one `Client` (person) can own several `Vehicle`s. `ClientService.resolveOwner` decides the owner when an ITP is saved (form or CSV import): same name as the current owner -> keep; a station client with the same name (`ClientKeys.nameKey`, no diacritics/case) and phone (`clients.phone_key` = last 9 digits) -> that one; current owner has no other car -> rename; else a new client. Editing an ITP's plate moves only that ITP (to the car with the new plate, or a new car if the old one keeps other ITPs). Deleting an ITP/vehicle/client cleans up empty vehicles/clients and unlinks appointments (`ClientService.deleteRecords`). `ItpService.validate` checks the ITP form (400 `{"message","field"}` via `config/FieldException`; the same rules run in the browser in `utils/itpValidation.ts`, and `AddItpModal` marks the field in red; VIN = 17 letters/digits without I/O/Q, phone 9-15 digits). Throw `FieldException` for any new form-field error. Clients page `/clients` (`/api/clients/**`, MANAGER only): search, client file with cars + ITP history, edit client/car (plate collision -> 409), move a car, merge clients, possible duplicates (same phone or name), delete. V4 merged existing duplicate vehicles/clients.
- History (B2): `AuditService` writes `audit_events` (station `userId`, actor email, action CREATE/UPDATE/DELETE/RESTORE/MERGE/MOVE/IMPORT, entity ITP/CLIENT/VEHICLE, human summary, field-level `changes` "Label: old → new" per line). Log every user-visible change of ITPs/clients/vehicles; skip empty diffs. Deletes store a JSON snapshot (`ClientSnap` → vehicles → ITPs + linked appointment ids) and return the event id in the `X-Audit-Event` header (exposed via CORS); `HistoryService.undo` restores it within 30 days (reuses a car with the same plate, never duplicates an ITP, relinks appointments). Events older than a year are purged by the daily digest call. Frontend: deletes have no `confirm()`; they call `offerUndo` (`utils/undo.ts`) and the global `UndoToast` shows "Anulează" for 10 s; page `/history` (filters, restore button).
- Consent (C1, GDPR): `Client.reminderConsent` = GIVEN / DECLINED / null (unknown, legacy), with `consentAt`, `consentSource` and a personal `optOutToken`. The ITP form checkbox (`ItpFormDTO.reminderConsent`, null = don't touch) gives or withdraws consent via `ClientService.applyFormConsent` (unchecking never clears DECLINED); online booking stores it on `Appointment.reminderConsent` and it is prefilled into the ITP started from the appointment. DECLINED clients are filtered out of reminders (and so the daily digest); automatic sends (C2) must only go to GIVEN. Public STOP page `/stop/:token` (`/api/public/stop/{token}`), station toggle in the client file (`PUT /api/clients/{id}/consent`). Reminder messages get `{stop}` (appended on a new line when the template lacks it).
- Automatic SMS reminders (C2): per station `AppUser.autoSms*` (enabled, provider `SMS_GATE` = the station's Android phone via the "SMS Gateway for Android" cloud API `POST {smsgate.url}/3rdparty/v1/messages` with basic auth, or `SMSLINK` = `secure.smslink.ro/.../json.php` GET with connection_id/password; passwords write-only), stages in days (default 30,7) and an SMS template. `AutoReminderService.runDaily` runs inside the daily internal call: latest ITPs whose expiry falls in a stage window (stage .. stage-5 days), only consent GIVEN, mobile numbers, no NOT_INTERESTED/SCHEDULED status and no upcoming booked appointment for the plate; one `reminder_sends` row per (ITP, stage), FAILED retried up to 3 days, 300/station/day cap. `SmsText` renders without diacritics (GSM 160 chars) and appends the STOP link after rendering; `utils/smsText.ts` mirrors it for the preview. `SmsSender` never retries a request that may have left; custom SMS Gateway URLs must be https + domain (no SSRF). Settings card `AutoSmsCard` in Contul meu (`/api/account/auto-sms`, `/test`, `/log`).
- Landing page (`LandingPage.tsx` + `components/landing/*`): shown on `/` to visitors who are not logged in (`RootGate` in `App.tsx`); logged-in users get the app. Only real features and no invented numbers/testimonials; pricing shows the three plans (with VAT-inclusive prices) and the SMS add-on. Gallery images in `frontend/public/landing/` are screenshots of a fictive demo station ("ITP Exemplu", made-up names). The ROI calculator (`utils/roi.ts`) is an estimate from the visitor's own inputs. "Cere o demonstrație" posts to `/api/public/leads` (honeypot, 3/hour per IP, `leads` table, optional email to `LEADS_EMAIL`); admin sees them at `/leads` (`/api/admin/leads`).
- Public pages share `PublicHeader`/`PublicFooter` (`components/landing/PublicChrome.tsx`; company data in `utils/company.ts`: VLN SOLUTIONS, CUI RO48267925). `/statii` lists stations for drivers (`GET /api/public/stations`: active managers with online booking on and `AppUser.publicListing` != false, toggle in the booking settings card); below it "Caută stație ITP în zona ta" (`NearbyStationsSearch`, `utils/nearbyMap.ts`) opens a Google Maps search "stație ITP <oraș>" in a new tab / the Maps app. Free, no key, no backend call. Not Places (paid), not the Maps Embed API (its search mode shows no pins for category searches), never scraping. `/confidentialitate` and `/termeni` (`LegalPage.tsx`) are the legal texts; keep them in sync when adding processors (hosting, email, SMS, AI) or new personal data.
- Station logo and booking message: `LogoService` (any PNG/JPG/GIF/BMP is decoded with ImageIO, sources over 8000 px or 5 MB refused, redrawn as PNG ≤ 400 px, so no SVG / metadata) stored in `station_logos` (V28, `StationLogo`, separate from `app_users` so it isn't loaded on every request); `AppUser.logoToken` changes on each upload and the image is public at `/api/public/logos/{token}.png` (cached 1 year, immutable). `PUT/DELETE /api/account/logo` (multipart `logo`); `LogoService.path` goes into the profile, the public station, `/statii`, the `/p/:token` view and (absolute, with `api.url`) the client / manager booking emails; shown also on the poster and the ITP sheet (`utils/apiUrl.assetUrl`). `vercel.json` img-src lists the backend hosts. `AppUser.bookingMessage` (≤ 300 chars, Programare online card) is shown under the station name on the booking page.
- Booking emails, calendar and notifications: optional `Appointment.email` (V27; online form + manager modal, `BookingEvents.optionalEmail`). `BookingEvents` runs after an online booking / client move / client cancel: SMS confirmation, `AppointmentMailService` (client email with „Google Calendar” link + .ics link, manager email unless `AppUser.bookingEmailNotify` = false or the email isn't verified; failures only logged) and an in-app `Notification`. `CalendarLinks` builds the Google Calendar URL (ctz Europe/Bucharest) and the .ics (UTC, 1 h alarm) served publicly at `/api/public/appointments/{token}/calendar.ics`; the booking response and the `/p/:token` view carry both links (`AddToCalendar`). Notifications (`notifications`, kinds NEW_BOOKING / CLIENT_CANCELLED / CLIENT_MOVED / INSPECTOR_ITP / INSPECTOR_NO_SHOW, link `/calendar?date=`; `/api/notifications` MANAGER: inbox of 30 + unread, `/unread-count`, `/{id}/read`, `/read-all`; purged after 90 days by the morning run). - Appointments without no-shows (C3): every appointment has a `manageToken`; the client's SMS link `/p/:token` (`/api/public/appointments/{token}`, `AppointmentSelfService`) shows it and allows cancel / move to another free slot (`BookingService.availableSlots(..., excludeId)`) until 60 min before; client actions are stored in `clientAction`/`clientActionAt` and shown in the calendar. `AppointmentSmsService` sends, on the station's SMS channel and only when enabled (`AppUser.apptConfirmSms` / `apptReminderSms`, in the SMS card): a confirmation right after an online booking (and after a move) and a reminder in the daily run for tomorrow (Saturday also covers Monday), once (`reminderSentAt`). - Import (E2): `ImportCsvModal` reads .xlsx (`read-excel-file/universal`, lazy-loaded, no web worker) or .csv in the browser, guesses the columns (`utils/importMapping.ts`), lets the station fix the mapping with a preview, derives validity / ITP date from the expiry date when needed, and uploads the rows as our canonical CSV to `/api/itp/import` (`CsvImportService` stays the single import path).
- Invoicing (D3): `OblioClient` (oblio.eu API: token per email+secret cached ~1 h, companies / series / vat_rates, `docs/invoice`, `docs/einvoice`), `InvoiceService` + `/api/invoicing/**` (MANAGER): per-station settings on `AppUser.oblio*` (secret write-only), `Invoice` rows (one per fleet+month, one per ITP; 409 on a second). Fleet invoices come from `FleetService.statement` (one line per priced ITP; client = fleet CUI + `Fleet.address/city/county`), person invoices from one ITP. Optional SPV upload right after issuing (a failure is stored in `einvoiceStatus`, the invoice stays). UI: `InvoicingCard` (`/account#facturare`), `InvoiceButton` in the fleet statement (`FleetStatementView` `extra`) and the ITP details window.
- Subscriptions (E1): `AppUser.plan` FREE / PRO / PREMIUM (null = account from before E1: Premium without expiry), `planUntil` (last paid day, inclusive; null = no expiry), `planTrial`, `billing*` (company, CUI, address). `Plans` (backend) / `utils/plans.ts` (frontend, same prices, VAT included: Pro 59, Premium 99, SMS add-on 119/229/369; VAT 21% is inside the price and the Oblio invoice uses `vatIncluded`; 12 months billed as 10) define what each plan includes (`Plans.Feature`: AUTO_SMS, STATION_DEADLINES, OWNER_REPORTS = Pro; SCAN, FLEETS, INVOICING, REVIEWS = Premium) and the plan in effect (after `planUntil` → FREE, data kept). Gate a paid feature with `Plans.require` (402 `{"message"}`) in the endpoint and `Plans.allows` in the daily runs; whole modules by path in `config/PlanInterceptor` (`/api/fleets`, `/api/invoicing`); the fleet portal stays open. `SmsQuotaService.plan` is 0 on FREE. Self-service signup `POST /api/auth/signup` (`SignupService`: honeypot, 3/hour per IP, FieldException per field, admin notified on `LEADS_EMAIL`) and admin-created managers start a 14-day Premium trial (`BillingService.startTrial`). Payments (`BillingService`, `/api/billing/**`, MANAGER): `NetopiaClient` (API v2 `/payment/card/start`, `/operation/status`; sandbox by default) → redirect to Netopia → back to `/plata?order=` (`PaymentResultPage`, calls `/refresh`) and IPN `POST /api/public/netopia/ipn`; the state is always re-read from Netopia (never trust the IPN body) and applied once under a row lock (`PaymentRepository.lockByOrderId`); same plan extends after `planUntil`, a different plan starts today and converts the remaining days by price, a payment during the trial starts after its last day (`BillingService.applyPaid`, mirrored by `paidUntil` in `utils/plans.ts` for the "Activ până la" line in `SubscriptionCard`). No automatic renewal. After payment the platform's invoice is issued through Oblio when `PLATFORM_OBLIO_*` is set (errors stored on the payment). Admin: `PUT /api/admin/managers/{id}/plan` {plan, until} (e.g. bank transfer), `GET /api/admin/payments`. Frontend: `PlanProvider` (`context/PlanContext.tsx`, `usePlan` in `context/plan.ts`, wraps `Layout`) loads `/api/billing/status`; `PlanLock` / `PlanBadge` show what's locked with a link to `/account#abonament` (`SubscriptionCard`); `PlanBanner` shows trial days / expiry. Public `/inregistrare` (`SignupPage`); landing pricing lists the 3 plans + SMS add-on.
- Account emails (`AccountEmailService`, template `AccountMail`): welcome + email confirmation after signup (`AppUser.emailVerified` false; null = older account, treated as confirmed; `EmailVerifyBanner` in `Layout` with "Retrimite"), "Am uitat parola" (`/parola-uitata` → email → `/resetare-parola?token=`, 1 h, single use, revokes sessions; same answer whether the email exists; 5/h per IP, 3/h per email) and `/confirmare-email?token=` (7 days). Tokens: 32 random bytes, only the SHA-256 is stored (`auth_tokens`, `AuthTokenRepository.lockByHash`), a new link invalidates the previous one, expired ones purged by the daily run. `PlanNoticeService` (daily run) emails the station 3 days before `planUntil` and once after expiry (within 7 days), one per stage per date (`AppUser.planNotice`).
- Account data (GDPR, `AccountDeletionService`): `GET /api/account/export` = everything of the station as JSON (no passwords/API keys/tokens); `POST /api/account/delete` {password, confirm "STERGE"} closes the account now (`deletionRequestedAt`, inactive, sessions revoked, email) and the morning run hard-deletes it after 30 days (`purgeDue`); admin reactivation cancels, `DELETE /api/admin/managers/{id}?force=true` deletes now. `hardDelete` removes every station table by SQL (flush + clear the JPA session first); keep it in sync when adding a table with station data (inspectors, inspector_days, inspector_leaves, inspector accounts, line_shifts, notifications, station_logos and station_closed_days included). UI: `AccountDataCard` (`/account#date`). Terms have the art. 28 processing agreement (`/termeni#prelucrare`).
- Withdrawal function (OUG 34/2014 art. 11^1, EU 2023/2673): public `/retragere` (`WithdrawalPage`, link "Retrageți-vă din contract aici" in every public footer, the terms and the subscription card) → `POST /api/public/withdrawal` (`WithdrawalService`: honeypot, 5/h per IP, FieldException per field, links the account with the same email) → receipt email with date/time to the client + notice on `LEADS_EMAIL`; stored in `withdrawals` (V21, kept 3 years, unlinked on account deletion); admin list under the demo requests (`/api/admin/withdrawals`).
- Backups: `.github/workflows/db-backup.yml` daily `pg_dump` encrypted with gpg AES-256 (`BACKUP_DATABASE_URL`, `BACKUP_PASSPHRASE` secrets; the repo is public), artifact kept 30 days; restore steps in the scratchboard.
- SEO: `index.html` has the description, canonical and Open Graph tags (`public/og-image.png`, 1200×630), `public/robots.txt` (app routes and personal links disallowed) and `public/sitemap.xml` (public pages); page titles via `usePageTitle` (`utils/pageTitle.ts`; app pages get theirs from the nav in `Layout`).
- Guide (`/ghid`, `GuidePage`, content in `utils/guide.ts`): first steps checklist (kept per device), table of contents, search without diacritics, one section per feature with plan badge and deep links (`/account#<card id>`: statie, linii, programare, inspectori, termene, facturare, abonament, sms, recenzii, rezumat). Linked in the sidebar above the theme switcher and in the Contul meu header on phones. Update it when a feature changes.
- Data scoping: every manager query filters by `client.user.id`; legacy clients may have `user_id = null` and must be skipped.
- Same license plate (ignoring spaces/dashes/case, `PlateUtils`) = same vehicle; only the latest ITP per vehicle counts for expiry. The normalized plate is stored in `vehicles.normalized_plate` (set by `Vehicle` on save, indexed) and "latest" is computed in SQL (`ItpRecordRepository.LATEST`, a NOT EXISTS keyed on the normalized plate; keep the plate equality outside any OR or Postgres can't use the index). Don't load a whole station to filter in Java: use the targeted queries (`/api/itp/records` paged + search, `/summary`, `/history`, reminders window, GROUP BY stats for admin, date-ranged reports). `/api/itp/dashboard` (full list) is kept only for the CSV export and compatibility.

## Commands
- Backend: `./mvnw spring-boot:run` (profile `dev`) · build `./mvnw clean package` · test `./mvnw test` (H2 in-memory, profile `test`; no Postgres needed)
- Frontend (in `frontend/`): `npm run dev` (proxies `/api` → localhost:8080) · `npm run build` · `npm run lint` · `npm test`
- CI: `.github/workflows/ci.yml` runs backend tests + frontend lint/test/build on push.
- Docker: `Dockerfile` builds backend only (runs as non-root, `MaxRAMPercentage=75` for Render's 512 MB).
- Health: `/api/health` is DB-free (UptimeRobot keep-alive, lets Neon sleep); `/api/health/deep` also checks the DB. Frontend shows a "server is starting" banner when a normal request takes > 4 s (`utils/serverStatus.ts`, `ServerWakeBanner`).

## Deploy
- `main` auto-deploys: frontend on Vercel (`frontend/`, SPA rewrite in `vercel.json`), backend on Render (Dockerfile), DB on Neon.
